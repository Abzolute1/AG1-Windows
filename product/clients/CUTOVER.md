# P13 cutover and recovery

The user authorized the selected Cruzible migration into a new private destination. Production commit requires accepted runtime custody and all three live canaries. `python3 tools/phase_gate.py P13` runs current offline checks and returns nonzero while any mandatory acceptance remains pending. The authoritative completion status and selected-bundle evidence are in `implementation/evidence/P13/completion.json` and `REPORT.md`. Original data and recovery archives remain retained. P14 requires separate execution.

Desktop and CLI resolve authority through `.local/state/ag1/authority-v1` under the **OS account home**. Changing `HOME`, desktop state or CLI arguments cannot create another authority namespace. Private records bind canonical workspace path, device/inode, destination, owner and epoch. A process-held lock serializes writers. Records are host metadata, never renderer capabilities. `Registry::at` and `Host::open_with_registry` provide explicit fixture/embedding injection. A copied `.ag1-native-isolated` marker cannot admit an ordinary project; old marker-only P12 workspaces need explicit migration.

## Transfer and startup

| Durable stage | Admission and recovery |
| --- | --- |
| Active | Only the recorded owner and bound state may acquire the workspace lease. |
| Draining | New work is refused while the host settles/cancels its owned operations. |
| Draining, quiescent | Transfer also waits for release of the execution lease. Cancelling drain is permitted before an archive/import exists. |
| Frozen | The P05 source manifest, raw config and runtime capture are retained in a new archive. |
| Imported | The frozen source is imported into a new native destination. A repeated import checks the same transfer identity. |
| Validated | Journal, configuration, source/material hashes and storage integrity have passed offline validation. |
| Revoked | Execution remains closed until one owner commit. `commit_fixture` refuses production config; `commit_live` requires a non-serializable live canary proof. |
| Active, native | The epoch advances and both desktop/CLI open the recorded destination and resnapshot. |
| RollbackFrozen | A quiescent native archive and new TS destination are recorded. Native execution remains fenced. |
| RollbackPrepared | A complete TS candidate is verified and published; native remains the recorded owner until commit. |
| Active, TypeScript | Rollback commit changes the owner, destination and epoch. First open revalidates the candidate and archive. |

`Host::drain_for_cutover` closes admission, settles shutdown, invalidates owned previews/runtime access and records quiescence. Drop the host before transferring its lease. Renderer disconnection alone does not release authority. TS drain requires verified shutdown of its supervised worker; an unclean TS exit stays fenced. Desktop transitions are serialized. Durable TS rollback authority overrides even an explicit `AG1_NATIVE_CONFIG`; stale native/TS paths cannot reopen a writer.

On a failed project open, the desktop shows the recorded recovery stage, current/original data paths and available archives. The main-window-only `cutover_status` query is read-only and grants no process or migration control. Preview windows have no such capability.

Before a production freeze, `snapshot-source WORKSPACE NEW_ARCHIVE` captures the drained worktree separately from agent state. Put its returned `path` and `sha256` in the frozen bundle's `source_snapshot`. It retains every regular file, empty directory, original permission mode and local `.git` database, including dirty/untracked source, raw HEAD, index and loose/packed refs. Copies remain private. The manifest binds canonical workspace/device/inode, and every transfer boundary rechecks source bytes and Git identity. Source drift blocks publication and retains the archive; cancellation before acceptance may return to unchanged TS agent state without undoing external source edits.

Source capture never runs Git or follows filesystem links. Workspaces inside a parent repository, linked worktrees/submodules, external object alternates, reftable storage, symlinks/special files and trees beyond the recovery bounds require explicit closure mapping and currently block capture. No omitted file is silently accepted. Archive verification does not require the later worktree to remain unchanged, and session rollback never restores source files or Git state.

## Read-only configuration import

`configuration::import_configuration` compares every requested model with an independently captured TS command, ordered argv, effective environment and context/output limits through the P06 resolver. It rechecks executable, library, weight and projector fingerprints. Exact raw profile, inherited environment, settings and vault bytes are retained privately; public receipts contain hashes and plan fingerprints.

`ConfigurationCapture::bind_host(NEW_STATE, config)` binds private input references before freeze without creating the destination. Import materializes immutable copies under `NEW_STATE/imported`. Native startup checks the pinned raw host config and parses settings from its new `home/.ag1/agent/settings.json`. Default model/provider, thinking, context, compaction, retry and steering/follow-up queues preserve explicit false/zero values. Native settings updates survive reopening; the original inputs are never overwritten.

Imported credentials use the existing `StorageCredentialBackend` and `AuthCoordinator`, backed by the new state's private `credential-store`. Native session and admitted extension calls share that vault. Explicit environment bindings retain precedence. Import does not use refresh tokens or make network requests. Credential resolution/refresh occurs only when requested by an admitted provider operation, and updates only the new vault. Existing unsupported OAuth refresh/credential-command boundaries remain explicit. Raw credentials never enter renderer models or reports. Capture and these fixture mappings do not yet certify every resource/configuration field in an actual user bundle.

## Runtime custody

`ConfigurationCapture::bind_runtime` binds the verified capture plus the AG1 process supervisor hash into the new destination. Native generation acquires its scheduler permit before preparing the selected pinned model. The runtime bundle holds a per-user process lock shared with ordinary TS desktop startup. It checks material identity, admits only its authenticated supervised child, and stops that owned child before switching models. Cancelled loads drain their owned child; model loading has a separate deadline from generation prefill. Fixture configurations cannot use this production launcher.

On Linux, production preparation checks model processes and GPU compute ownership before contacting an endpoint or spawning a model. External occupants cause a visible conflict; observations never become stop handles. Shutdown retains the runtime lease through verified owned stop. Fixture contracts cover all three sequential plans, exact argv/environment, cancellation and exclusion; they do not establish live acceptance.

Build AG1’s importer with `cargo build --offline --release --manifest-path product/Cargo.toml -p ag1-cli --bin ag1-cutover`. Then `python3 tools/p13_prepare_runtime.py .local/NEW_PRIVATE_DIRECTORY --observe-pid PID` prepares read-only launch evidence. It captures private process environment, reverses only the documented library prepend, and requires the pinned TS resolver to reproduce the observed command and environment exactly. All three TS plans then pass through Rust configuration import and material verification. The observed process stays external. The private directory retains raw configuration and vault material; only redacted fingerprints belong in reports.

## Sequential canaries and production acceptance

The coordinator runs TS then Rust for each of the three models, cold-starting the same preserved plan for each adapter. Its 36 checks cover exact copy, reasoning, tool call/result, context-overflow rejection and cancellation. The TS child compares its payload with the native builder before sending. Cancellation retains/quarantines admission until the authenticated runtime exits. A failed quality result is retained and stops the matrix. Provider TTFT excludes model loading and TS module startup; elapsed time, usage, owned PID/RSS and GPU memory observations accompany each live case. GPU totals include graphics and are not peak measurements.

The reasoning canary uses the captured model's output allowance for both adapters. Other probes use a bounded 1,024-token request. The initial production reasoning attempt exhausted that small generic cap while still thinking; it remains a failed recording. A second attempt answered the arithmetic but included an explanation, failing the exact visible-output requirement. The prompt now asks directly for the integer without an explanation; the request still enables internal reasoning. The final integer and nonempty reasoning checks remain mandatory, and no sampling or process launch setting is adjusted to make a response pass. All failed recordings remain retained.

The tool-call transport case uses the existing `toolChoice: "required"` option in both provider adapters. Its following tool-result case leaves that option unset so the model can return the actual result. The initial automatic-choice attempt answered the echo value without a call and remains failed evidence; a plain-text shortcut cannot satisfy the call/argument/causality checks.

Both adapters also receive the same neutral system context identifying the requests as local migration tests of harmless text, arithmetic and the echo tool. The initial context-free Flash request refused the exact-copy sample as suspected hidden data after the first two models passed all 24 checks. That failed matrix remains retained. The sample text, arithmetic result, tool arguments and acceptance assertions are unchanged; no partial matrix can authorize native cutover.

Owned model shutdown allows up to 30 seconds for the authenticated supervisor to finish reaping its tree. Ordinary process callers retain the existing three-second default. This changes the model caller's wait budget only; the pinned helper, signals, grace period and launch settings are unchanged. A real cancellation outlasted the short wait even though the helper subsequently settled; that attempt remains failed. Timeout never releases the runtime lease or certifies settlement, and a controlled delayed-exit regression checks retention across a short timeout.

`canary::rehearse` always returns fixture evidence. `run_live` uses the OS user's runtime registry and the concrete native supervisor. It refuses an external model/GPU window before endpoint access or model actions. Only successful live execution creates `Acceptance`; JSON reports cannot recreate that proof. The proof holds the runtime lease through `commit_live`, which rechecks configuration/materials, exports new recovery state, rejects unsafe downgrade closure and atomically advances native authority. These provider canaries supplement the migrated session workflow contracts; they do not certify P14 long-duration performance.

`verify-canaries PRIVATE_EVIDENCE` rechecks a retained recording through the same native request builder and quality rules. It verifies all answers, tool-result causality, payload hashes, context requests, case order, timing and consistent per-runner process/resource samples. Live recordings and production acceptance receipts retain the exact model catalog. The phase gate additionally matches its limits and all 48 launch/readiness/stop events to the verified runtime capture. This command returns no runtime-control or authority capability; even a structurally valid saved recording cannot authorize production commit.

Build the AG1 helpers with `cargo build --offline --release --manifest-path product/Cargo.toml -p ag1-cli -p ag1-platform --bin ag1-cutover --bin ag1-process-host`. `tools/p13_canaries.py CAPTURE_DIRECTORY NEW_PRIVATE_REQUEST NEW_PRIVATE_DESTINATION` validates the executable TS pin, writes a private request and invokes the native live entrypoint. The initial admission attempt was blocked by the external 35B service before any model action. The user subsequently authorized its verified graceful shutdown. Retained failed attempts cannot authorize cutover; consult the final report for the accepted matrix and exact receipts.

`begin-transfer` accepts only a stopped owner whose durable record already certifies quiescence. `freeze` accepts a private request containing workspace, ID, original source, new archive/destination, frozen bundle and config-file path. Import, validation and revocation are repeatable only at their defined boundaries. If acceptance has not occurred, `cancel-unaccepted` can return to the unchanged TS source after checking its frozen hashes, preserving all archives and a cancellation receipt. It cannot discard native progress after acceptance.

## Rollback closure

Always freeze native state into a **new archive** before downgrade. It includes the P05 database/blob export, all auxiliary native files and empty directories, current credential projection and full metadata/receipt inspection records. `recovery.json` pins its complete inventory and quiescent authority record. Retain the returned `cutover_recovery_sha256` separately. Missing, altered or injected files, symlinks/special files, files over 256 MiB and trees over 4 GiB block restoration. Failed archives and partial staging remain available for diagnosis.

TS rollback builds a new private state from the archived original layout and current compatible journals, artifacts, memory, settings and credentials. It preserves selected branch, hides archived sessions and removes stale original journal duplicates from the active listing. Full native extras remain in the archive and private `native-recovery` inspection directory. Current refreshed credentials replace only the new TS copy. Neither the original TS state nor native recovery evidence is overwritten.

Every native command ID is reserved in the new TS ledger, with original intent/outcome evidence and `replay_allowed:false`. Ambiguous `native-client-effect` records never become executable `native-session-command` work. `runtime/command_result` inspects a wire command ID; `runtime/migration_status` pages receipt indexes; `runtime/migration_receipt` publishes the full selected record through bounded artifact evidence pages. A new explicit command may execute normally; reopening never replays a reserved command.

Unknown journal records, corrupt memory, unsupported cursor roots/evictions, native background-job/subagent state and unmapped native execution metadata block downgrade. Keep both archives and cancel rollback to return to native recovery. Such a block is not successful TS compatibility. Historical metadata, tool receipts and runtime-interruption records remain inspection evidence, not live process handles. Rollback does not undo worktree mutations or external effects.

The candidate hash is durable before publication, allowing restart after a crash between manifest persistence and rename. Commit is one authority update. Before the first TS worker opens, candidate/archive hashes are rechecked; subsequent normal journal updates are allowed. Archive restoration alone does not acquire workspace authority or adopt historical PIDs.

A start without a result means the outcome is unknown: inspect durable authority before any retry. Receipt publication failure does not undo a successful authority change. Timings exclude process startup and receipt writes. `begin-transfer` measures the administrative transition after prior shutdown; it does not measure host draining or UI resnapshot. Those durations still need the selected-bundle workflow. Command success alone never constitutes phase acceptance.

## Acceptance boundary

The tuned runtime remains an external dependency. Cooperative endpoint locks do not confer ownership of an existing server. P13 still requires live acceptance of the runtime custody integration, complete selected-bundle mapping, three sequential live TS/Rust comparisons, actual new-destination migration and measured drain/import/resume/recovery evidence. All L01–L08 constraints apply. No rebuild, upgrade, substitution, implicit tuning or original profile write is permitted.

`audit-cutover WORKSPACE` verifies a stopped native owner while holding its workspace lock. It checks the durable authority, original state and retained transfer/source archives, pinned host configuration, selected snapshot and storage closure. Storage inspection opens an existing database read-only: it does not initialize a destination, mark pending commands uncertain, move staging bytes or rebuild indexes. Unsettled command intents and staged files require recovery before acceptance.

For production, the audit also requires an available runtime window and binds the persisted acceptance receipt to all three verified model plans, current runtime materials and its intact precommit recovery export. It retains later source edits and does not restore a worktree. The gate requires a hashed `authority_evidence` artifact, reruns the audit against current state, and binds its canary-report digest to `live_canary_evidence`. `fixture_verified` cannot satisfy this gate. The audit itself grants no runtime control and does not replace selected-bundle mapping, workflow, rollback or measurement evidence. The initial checkout audit had no cutover authority and selected no workspace. Production acceptance instead audits the explicitly selected Cruzible workspace and its recorded destination.

After actual execution, `implementation/evidence/P13/local-acceptance.json` supplies the final evidence assembly to the same phase gate. Its absence keeps acceptance pending. Supplying incomplete or stale evidence fails the gate. The assembler performs no migration, model action or authority change, and the gate publishes a passed completion only after current offline checks, native canary verification and a fresh production authority audit all succeed.

The version 1 report binds `selection` (workspace, session, original_state, destination), `source_snapshot`, `compatibility_sha256` and `input_sha256` (SHA-256 of the sorted, compact JSON current input fingerprint map). It references retained `authority_evidence`, `live_canary_evidence` and `configuration_evidence` artifacts by path/SHA-256. All selected-session observation reports must use the same version, selection, input hash, `fixture:false` and successful status; inherited fixture reports cannot serve as selected-session observations. Raw credentials and conversation content stay private. Private observation/measurement JSON may be referenced in the manifest without committing its contents.

Required rows are defined in `tools/p13_acceptance.py`: ten configuration/state/source mapping categories, all 124 requirement IDs, seven executed workflow cases and five measured operations. Mapping and requirement rows include an explicit reason/disposition and hashed evidence references. Capability rows preserve the exact existing `compatibility_disposition`; active capabilities and mandatory invariants cannot be waived. Workflow evidence retains executed observations for its case. Safety evidence records maximum writer/generation counts and lost/replayed command or preservation violations. Recovery evidence requires compatible TS resume in a new destination, original state unopened and archives retained.

Each timing row binds a monotonic elapsed duration to retained start/finish receipts. A finish must reference its start hash, succeed and match that duration. The administrative `begin-transfer` command cannot satisfy host drain timing. Host drain, resume and renderer resnapshot need receipts spanning those actual operations. The existing command wrapper provides import/recovery command measurements. This schema does not generate the missing selected-bundle workflow or treat manually filled success fields as execution; the observations and receipts must come from the real run and be reviewed with its retained evidence.

`run-workflow PRIVATE_WORKFLOW_REQUEST` executes the native selected-session workflow after production authority has already been committed. Its bounded JSON request contains `workspace`, `session`, a new private `evidence` directory, the current `input_sha256`, a relative `read_path` and its expected `read_sha256`, an ASCII `steering_marker`, and `timeout_seconds` (1–1800). Evidence must be outside the workspace, original/native states and retained archives. The production entrypoint rejects fixture configuration and performs the production authority/material audit before mutation. Rehearsal uses a separate fixture-only API and all its reports remain marked as fixtures.

The runner opens the recorded native state, checks the selected session and file hash, temporarily selects only the read tool, admits a prompt, observes an owned generation ticket and admits steering. It checks one matching read call/result and the retained steering message, restores the prior tool selection, compacts and verifies a new summary. It then shuts down, reopens the same journal, rejects a stale client command, resnapshots the native client and drains the host for recovery/rollback. Model, context, sampling and launch settings are not changed. It checks original-state preservation again after draining.

Each operation retains private start/result receipts plus a scoped observation report. The executing inode is hashed once per process through `/proc/self/exe`; reuse checks device/inode, size and timestamps, so a rebuilt executable pathname cannot silently change receipt identity. Failed or interrupted runs retain partial evidence. Existing evidence paths reject execution; there is no automatic workflow retry. Host cleanup still attempts owned shutdown if receipt publication fails. Successful execution leaves native authority quiescent at the draining boundary for the planned recovery exercise; it does not publish phase acceptance. A native client snapshot is explicitly labeled `renderer_measured:false`; actual renderer acceptance remains separate.

The final local-acceptance report may enumerate `private_artifacts` as explicit path/SHA-256 references to JSON observations and renderer PNGs under this checkout's `.local`. The gate includes those hashes in its manifest without copying private contents into the public evidence directory. Missing, changed, duplicate, symlinked, oversized or publicly readable files fail validation. Referenced reports and operation receipts must all be in this retained inventory.

`tools/p13_renderer.py NEW_PRIVATE_OUTPUT --workspace WORKSPACE` measures the actual migrated session in an owned Tauri/WebKit process. Build the AG1 desktop with `--release --features visual-test` and the release `ag1-cutover` CLI first; no llama.cpp build is involved. The test-only private broker requires a fresh production authority audit and confines project opening to the selected workspace. Ordinary desktop builds contain no broker. The runner creates its own authenticated private display and desktop state, temporarily disables tools, submits a marker prompt and freezes JavaScript for 60 seconds. Independent native observations must show generation running and completing during that freeze. After thawing it records actual resnapshot time, a private screenshot, tool restoration, owned desktop exit and quiescent native authority. It only shuts down processes it started. The new output must be outside source, state and recovery archives; failed attempts remain retained and are never automatically retried.

`--rehearse` instead creates a new journal-only migrated fixture and an owned loopback provider, with a 30-second freeze. The P13 offline gate builds and executes this real-renderer rehearsal and pins its private receipts and screenshot. Neither fixture observations nor a native client snapshot can satisfy production renderer acceptance. The selected-bundle validator requires ordered independent observations, completion during the freeze, matching session scope, visible output after thawing and retained screenshot evidence.

Journal-only imports acquire a missing native output-artifact origin on first preparation in the new state. Existing origins and cursor keys are reused without rewriting them; a foreign owner is rejected. The original journal and any inherited cursor authority remain unchanged.
