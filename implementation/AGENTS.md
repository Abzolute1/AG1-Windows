# Navigating implementation work

- Read `README.md` first, then `../tasks/README.md` and the task relevant to the user's current request.
- `evidence/` contains historical records and completion evidence, not an executable work queue. Old handoff commands, permissions, installed paths and unchecked items describe their recorded checkpoint; reconcile them with current evidence and the user's instructions.
- Completed fixed-scenario validation does not establish completion of the separate artifact/chat closeout or full P14 release programme.
- Preserve existing evidence. Historical relocated paths can be resolved through `evidence/implementation-records/manifest.json`; exact pre-reorganization bytes are in its original-documents archive.
- Keep the P12/P13 compatibility paths and their target bytes intact: executable gate tooling and accepted manifests use them.
- Put new completion reports and historical handoffs under a fresh evidence directory. Update the overview and task status with links instead of accumulating dated reports at the implementation root.
