## Assessment

V4 has a technically justified load-time hypothesis: move private writable page fault/COW preparation out of serial CUDA registration into a bounded group of CPU workers. Its worker completion and registration order are sound for the restricted single-model lifecycle. A shorter `pin_seconds` alone would not prove improvement: compare original load plus prefault plus collapse plus registration, followed by first inference. The reported approximately 3.5-second serial pin cost is supplied by the parent, not measured by this review.

The optional collapse operation has no guaranteed benefit on the existing private file VMA. The anonymous replacement proposal offers a clearer THP eligibility route, but requires stronger provenance and fail-closed handling than v4 currently needs. It is suitable for a fixture experiment once the conditions below are implemented; source inspection alone does not establish runtime correctness or speed.

## V4: verified behavior and remaining limitations

1. **Byte-preserving preparation.** `prepare_private` at v4:75 divides validated CPU page spans into disjoint 32 MiB jobs, then calls `MADV_POPULATE_WRITE` at :98. This advice prefaults writable mappings and can break COW without an application write; failures can leave partial preparation. An OOM kill remains possible. Collapse is synchronous, best effort, can incur copying/reclaim/compaction and can partially succeed. File-backed THP eligibility has restrictions including executable mappings for ordinary file-backed cases; this RW private GGUF VMA must not be assumed eligible. Accept and record rejection without adding executable protection or changing system policy. [Linux madvise documentation](https://man7.org/linux/man-pages/man2/madvise.2.html)

2. **Workers complete before pinning.** The `std::jthread` vector at :88 is cleared at :102; destruction joins all workers. The lambda does not consume a stop token, so destructor stop requests do not abandon queued jobs. Collapse follows the join, and `cudaHostRegister` follows `prepare_private` at :192–196. Thread-construction/allocation failure unwinds existing `jthread`s before the outer catch terminates the experimental process at :210. This needs C++20 compilation; do not accidentally compile as the older standard used by an earlier shim.

3. **No new initial-upload overlap.** The hook invokes original model loading first (:162). Original mmap GPU upload uses synchronous backend tensor set (`src/llama-model-loader.cpp:1574`, CUDA copy and stream wait at `ggml/src/ggml-cuda/ggml-cuda.cu:855`). Validators finish at loader :1667–1673 and final trim at :1683–1688 before success. Thus this new preparation phase is after the known source users from initial loading. This statement is scoped to the inspected original implementation, no active inference/cache users and one selected load per process.

4. **Preparation failure is currently a performance fallback.** Failed prefault jobs log errno and continue. CUDA registration can perform remaining preparation. Final `complete=1` means collected ranges registered, not that every prefault or collapse succeeded. `bytes` counts successful whole jobs, not partial population; `collapse_bytes` likewise counts only completely successful advice calls. Collapse failures at :111 omit errno; add that diagnostic before interpreting an unsupported or memory-pressure result. All-or-nothing registration rollback is retained at :201, independent of advice success.

5. **Affinity and memory cost need observation.** Workers request CPU IDs 0 through count−1 (:90), log affinity failures and continue. This matches the current physical-core selection assumption, but does not prove placement under a restricted cpuset. Record the actual environment. More threads may contend in kernel fault handling and memory bandwidth. Private preparation can materialize anonymous copies of CPU-weight pages while file cache remains resident; it does not promise lower system memory use. Measure private/anonymous RSS and available system RAM, not just the mapped virtual size. Prefault/collapse can move latency earlier without reducing it.

6. **VMA validation remains narrowly adequate only under current assumptions.** `mapped_range` (:47) checks readable/private, continuous address coverage and pathname. It does not verify writable permission, device/inode, or file-offset continuity. Writable permission follows from this exact interceptor at :126 only if no other mapping/protection intervention occurs. Strengthen identity/offset checks before destructive anonymous replacement. Capturing original mapping identity also avoids assuming a pathname can never be replaced during the process.

7. **THP observability.** This host reports a 2,097,152-byte PMD hugepage size at `/sys/kernel/mm/transparent_hugepage/hpage_pmd_size`, matching v4:106. Record the value rather than generalizing the literal. Kernel THP documentation distinguishes actual huge pages from huge PMD mappings, describes possible PMD splitting after partial mapping/protection changes, and exposes allocation/collapse/compaction counters. Use per-range `/proc/PID/smaps` snapshots before and after registration and inference, with `AnonHugePages`, `FilePmdMapped`, `THPeligible`, RSS and private-memory fields; supplement with system counters as contextual data, not process-exclusive evidence. Do not infer retained TLB benefit from one successful collapse call. [Kernel THP documentation](https://docs.kernel.org/admin-guide/mm/transhuge.html)

## Proposed MAP_FIXED anonymous replacement

The proposal is to replace only the validated, merged CPU tensor page intervals at identical addresses after original loading, then `pread` original file offsets directly into those anonymous intervals, finally register them. It is not present in the reviewed v4.

`MAP_FIXED` replaces overlapping mappings, while an anonymous mapping initially contains zeros. Its safe use requires exclusive ownership of the exact target address interval; reserving an unrelated address or checking a pathname without lifetime control is insufficient. `MAP_FIXED_NOREPLACE` is not a substitute for intentional replacement of existing pages. Private and anonymous storage do not write back to the GGUF. [Linux mmap documentation](https://man7.org/linux/man-pages/man2/mmap.2.html)

### Compatibility with this original loader

- `llama_mmap::impl::mapped_fragments` contains address offsets, initially the full mapping (`src/llama-mmap.cpp:443`, :475). `unmap_fragment` trims full pages and updates those intervals (:478–523). The destructor simply `munmap`s each retained address interval (:526–530), without checking whether its pages remain file-backed. Replacing a subset of an already-retained interval at the same addresses is therefore compatible with that destructor. Do not extend beyond retained ownership, recreate a trimmed hole, or expand a CPU range outward to a hugepage boundary that crosses ownership.
- Original final trim has already run before the hook. Current post-load VMA validation rejects holes. Require every replacement to stay within these validated retained pages. Outward base-page rounding may include padding or neighboring tensor bytes; restore every byte in the entire replaced page interval, not only the named CPU tensor bytes. GPU values are already uploaded, but preserving page neighbors also protects aliases and later readers.
- The CPU buffer-from-pointer callback does not own/free its pointer (`ggml/src/ggml-backend.cpp:2590–2592`). Model `ctxs_bufs` destruct before `mappings` (`src/llama-model.cpp:1032`, :1039). Current shim free calls original buffer free, allowing MoE-cache invalidation/draining (`ggml-backend.cpp:220–225`), and unregisters only after the final CPU wrapper drains (v4:238–258). This order remains appropriate for anonymous replacement. Never leave an anonymous allocation separately owned by an allocator that also frees it; the mmap object's retained interval remains the sole unmap owner in this design.
- Source addresses stay stable, but contents temporarily become zeros/incomplete reads. This phase must have no inference, validation, cache-fill, debug callback or external reader using these tensors. No existing CUDA registrations or mlock assumptions may survive replacement. The inspected original successful load establishes upload/validator quiescence; concurrent model consumers require a separate ownership protocol and are out of scope for the experiment.

### Required implementation safeguards

1. Capture or duplicate the original read-only FD while intercepting the selected mmap, along with `fstat` identity, file size, mapping base and original file offset. Retain it until all reads join. Before replacement verify each covered VMA's device/inode and offset progression against that identity. Merely reopening the same pathname after loading can select another file. Even a retained FD does not prevent another process from mutating its inode: preserve the existing read-only-model experiment assumption and recheck metadata as a useful guard, not proof of immutability.
2. Precompute validated spans, source offsets, jobs and bookkeeping before the first replacement. Verify arithmetic, positive lengths, page alignment, mapping size and file boundaries. The existing map starts at file offset zero, so `span.begin − original_base` is valid only after that identity/offset proof. Current v4 rejects page rounding beyond logical `map_end`; retain that fail-closed limitation unless deliberately implementing and testing the final partial EOF page. Never demand a full-page read beyond EOF and mistake it for valid tensor data.
3. Once any replacement succeeds, incomplete read, mmap failure, worker exception or inconsistent range state must terminate this experimental process. Returning a partially zeroed model as ordinary mmap fallback is invalid. Check each mmap result equals the requested address. A registration failure after all bytes are restored can roll back pins and leave usable anonymous weights, but label this **anonymous unpinned fallback**, not ordinary mmap.
4. Use disjoint destination intervals and independent explicit file offsets. `pread` does not change the shared file offset; a successful call can return fewer bytes than requested. Loop on short reads, retry `EINTR`, reject zero before the expected end and propagate other errors. Keep requests reasonably bounded and join every reader before advice/registration or returning the model. [Linux pread documentation](https://man7.org/linux/man-pages/man2/pread.2.html)
5. Do not first issue a separate `munmap`: replace the owned interval directly, avoiding an unnecessary interval-reuse window. This does not remove the need to serialize model teardown and mapping changes. Registry locking only protects shim bookkeeping; it is not a process-wide memory-ownership lock.
6. Never `MADV_DONTNEED` restored anonymous weights. Current release hook's exact-file VMA guard (:228) rejects anonymous source ranges, which is useful. A lasting implementation should explicitly track anonymous/pinned spans as protected rather than relying only on pathname parsing. Review every release path, including future generic arena reclamation. Anonymous zero-fill after discard would corrupt weights.
7. If testing THP, apply per-range advice before population/registration and keep all advice bounded to the actual owned spans. Do not enlarge a mapping to 2 MiB boundaries over neighboring data. Divide interior work at hugepage boundaries where convenient to avoid two workers first-faulting the same hugepage; byte-disjoint jobs are already necessary for correctness. Complete any explicit collapse before pinning. Record failures and retained actual hugepage coverage after pinning; a non-THP fallback is valid data, not a proven optimization.

### Copy and memory claims

This design eliminates a separate full temporary destination arena: `pread` populates the final anonymous addresses directly. It still transfers file/page-cache bytes into anonymous pages, and may reread bytes touched during original prefetch, validators or initial GPU uploads. It therefore does not mean “zero-copy” or elimination of page-cache plus anonymous physical duplication. The comparison with writable COW is parallel read/fault cost and possible TLB coverage, not removal of all data movement. Advancing this into the loader's first CPU fill can remove the post-load refill phase; the shim alone cannot claim that benefit.

## Minimal source-owned route

For a maintainable variant, prefer a model-owned CPU weight arena with explicit mapping/registration RAII over process-wide mmap interception. The original non-mmap host path already seeks and reads directly into final `cur->data` (`src/llama-model-loader.cpp:1579–1585`). Allocate final anonymous CPU storage before that read, advise it for THP locally, read weights directly, finish validators and optional collapse, then pin before publishing the model. This can avoid both a second full application copy and MAP_FIXED replacement of a published file mapping. GPU-only tensors can retain the existing bounded pinned staging/upload path (:1588 onward).

Keep canonical quantization/layout and current CPU-host backend semantics. The existing CUDA-host allocator uses `cudaMallocHost` and frees with `cudaFreeHost` (`ggml/src/ggml-cuda/ggml-cuda.cu:1346–1378`); anonymous mmap storage requires its own unregister/munmap owner and must never flow to that free callback. Do not globally replace the allocator: the same mechanism also serves staging and other non-model allocations. A model-only allocation intent or selected weight-buffer API is needed. Preserve cache-user drain before unregistration and unmap, including cancellation and partial construction.

This is a loader/backend ownership change, not an arithmetic or quantization change. If implemented inside GGML/backend code, apply the exact experimental tree AGENTS.md required gates, including actually exercised CPU/CUDA backend cases. The proposed external fixture does not replace those gates or model validation.

### Corrections implemented

- The selected mapping captures an `F_DUPFD_CLOEXEC` copy of the original read-only descriptor, requires a regular file and exact mapping/file length, and saves its stat identity (:197–205). VMA validation now checks device, inode and file-offset continuity, in addition to private/readable path coverage (:52–66). At any cursor inside a VMA, `file_offset + cursor − VMA_begin == cursor − original_map_begin` is the correct relationship for the captured offset-zero original mapping, including fragments whose starts moved after trim.
- Collection stops after successful original load and before replacement (:247). Every merged range is validated before preparing any anonymous span (:270–275). Replacement uses a direct fixed anonymous mapping (:103); tensor addresses are unchanged, and all bytes in the outward-rounded page interval are read, not only tensor payloads. Original retained-fragment cleanup therefore remains compatible for the reasons established above.
- Read jobs are byte-disjoint. The explicit-offset read loop handles interruption and short reads and terminates on premature EOF/error (:81–89). Each job's file range is bounded by captured file size before read (:117–119). Since the original size is a nonnegative signed `off_t` regular-file size, validated offsets and their completed increments remain representable for this GGUF. Workers join before collapse, optional full-byte comparison, post-read stat checks and CUDA registration (:122–145, :281).
- Optional verification compares the entire replaced page ranges against the retained descriptor using only one 32 MiB scratch buffer (:135–142). This covers shared boundary-page bytes too. The post-read identity, size and nanosecond mtime comparison (:145) detects ordinary changes during loading. Neither this nor a retained FD makes concurrent external writes impossible; the model-must-remain-immutable assumption still applies.
- Anonymous ranges fail the exact-file VMA guard in the release hook (:313), so normal subsequent tensor uploads do not discard anonymous weights. The existing final-owner cache drain, unregistration and later mmap destruction order is unchanged (:323–345). Registration failure rolls back previous successes and correctly reports an unpinned-host fallback (:286–292).
- Collapse failures now log errno in both anonymous and private preparation (:131, :186). Allocation or thread-construction exceptions after a replacement unwind joined workers and reach the post-load terminating catch (:295–297). Building the jobs vector after each replacement is less tidy than allocating all bookkeeping first, but the current fail-process policy prevents a partially restored model from escaping on that exception path.

### Remaining concrete issues and scope restrictions

1. **Failed-load state is not fully reset.** The descriptor is acquired before the selected mmap syscall. If mmap fails (:209), it is not closed/reset. If original loading fails before any tracked CPU owner exists, `if (!model) return model` at :244 likewise leaves descriptor/range/collecting state behind. Cleanup at :344 only runs after the last tracked CPU wrapper is freed. A retry can subsequently hit the concurrent-mapping exit even without a live model. This is a real descriptor/state leak and reusable-process limitation; it does not affect an isolated successful one-load benchmark process. A model/mapping RAII owner, or explicit selected-load failure cleanup after original teardown completes, is required for integration.

2. **Concurrent mapping rejection is not atomic.** The load/check at :202 and store at :205 can both be passed by two threads; `original_stat` is also unprotected global data. Thus the message says concurrent loading is unsupported, but the code does not reliably exclude it. Enforce one load at a time outside the shim for current experiments. A reusable implementation needs a generation-bearing state machine or mutex/CAS acquisition before touching the shared identity, rather than treating two independent atomics as an ownership protocol.

3. **Release validation and replacement are not a general concurrent protocol.** The release hook validates a file VMA at :313 before taking the registry lock at :317. A concurrent replacement could make that validation stale; especially after registration rollback, its later discard could reach anonymous pages. The current original-load→prepare→publish sequence prevents such a concurrent reader in the intended run. Do not enable concurrent loaders, existing cache jobs or inference during preparation. Moving validation under the relevant lifetime lock and explicitly excluding anonymous intervals would be required if that scope changes.

4. **No explicit mlock or outside-registration rejection.** `params.use_mlock` is not checked. Original loader mlock tracking at `src/llama-model-loader.cpp:1565–1567` assumes its original mapped pages remain the locked storage. Anonymous replacement does not preserve that ownership merely by preserving addresses. Keep `use_mlock=false` and no third-party registrations, preferably assert these experimental prerequisites before loading. The subsequent CUDA registrations cover this shim's own page set; they are not proof that preexisting lock/registration lifetimes were preserved.

5. **Coverage is based on observed allocation hooks.** `complete` requires no recorded collection failure and at least one tensor (:270), not equality to an independently known expected tensor set. For the exact CPU20 placement, assert the expected 60 tensors in checkpoint evidence and compare the actual names/extents if this is to become a loader feature. The inspected standard host-to-device tensor-copy path uses `src->data` plus `ggml_nbytes(src)` (`ggml/src/ggml-backend.cpp:629–632`), which matches the collected tensor envelope. This supports that ordinary copy path; a clean actual high-batch run remains necessary for scheduler/cache-specific copies and CUDA's treatment of the registered page boundaries.

6. **Some edge diagnostics remain weaker than their labels.** EOF at :86 can print a stale errno, although it still terminates safely. `atoi` accepts a numeric prefix with trailing junk. `mapped_range` still does not test writable permission, relying on the original selected interceptor and no outside `mprotect`. Base-page size and address-rounding arithmetic retain the v4 assumptions. None was found to change bytes on the current ordinary Linux64 model path; make them explicit checked invariants before general use.

### Bounded disposition

No new blocking byte-preservation, original-fragment ownership or registration-lifetime defect was found for a single successful, sequential load with immutable GGUF, no mlock/previous registrations and no external tensor users. This is a conditional source-review conclusion, not evidence that CUDA registration, peak memory or real inference improves. The disposable fixture is useful evidence for mapping/read/THP mechanics but does not exercise real tensor layouts, expert DMA, cache draining or model teardown. Proceed only with the already planned isolated model checkpoint, complete logs, actual correctness checks and required backend gates; preserve failed variants as failed evidence rather than production fallback claims.
