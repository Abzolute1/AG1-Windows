# Native session runtime

`ag1_core::runtime::SessionRuntime` owns the committed branch, configuration and request/persistence barriers. `ag1_platform::session::NativeSession` executes its actions through real SQL storage, context compilation, native tools, HTTP providers and the shared endpoint scheduler. `RuntimeRegistry` prepares, drains and selects one runtime; `RuntimeCommands` exposes correlated commands across session changes. These APIs have no GUI, TUI or TypeScript AgentSession dependency. P10 acceptance evidence is in `implementation/evidence/P10/completion.json`; that executed report determines phase status.

The embedding supplies an authorized `Store` and artifact origin, explicit `Workspace`, bounded `BlockingPool`, shared P06 `Scheduler`, configured `ProviderHttp`, host `ProviderResolver` and `ToolRunner`. Credentials, endpoint ownership and process control stay behind host ports. Root, summary, episode and child calls use the same scheduler. No model launch or tuning is implicit in session construction or model selection.

Every request waits for accepted events, tool outcomes, journal writes and compaction. Preparation captures current branch, task, tools, thinking, model and resource configuration, retains complete input, compiles a bounded projection, and enforces the hard context margin. Async resolution and scheduler admission recheck configuration plus source/memory witnesses; changed inputs rebuild an unsent request. Failed persistence blocks subsequent inference. Provider progress precedes durable acknowledgment and cannot stand in for it; listener exceptions cannot interrupt internal custody. Returned partial and complete provider snapshots are retained before journal validation.

`NativeToolRunner` composes P09 file/search/Git/shell/jobs/web/target ports with task, memory, todo, observation, source-context, repository, episode and artifact actions. Preflight and final outcomes preserve source order; eligible independent execution is concurrent and file mutation serialization remains below dispatch. Original output precedes hook projection and aggregate limits. Invalid, rejected and aborted calls have durable outcomes; effect receipts never grant automatic reexecution. Loaded inspection IDs, verified results and historical evidence remain separate. B01–B04 corrections are exercised through native sessions and storage.

`run`, `continue_with`, `compact` and `navigate_tree` retain ownership of accepted workers across caller loss. Compaction reserves before cancellation/drain, externalizes exact trajectories, runs split summaries sequentially and publishes epoch/suffix changes only after acknowledgment. Automatic failure may create an explicit recoverable emergency checkpoint; stale captures, cancellation and lost custody cannot do so. Manual failures remain errors. Retry/overflow share one recovery arbiter and retain abandoned records. Replay excludes only an eligible terminal failure and rechecks the current owner. Quarantined transports keep their endpoint permit until host reconciliation. Parent reasoning has no new arbitrary deadline; summary and caller-provided child budgets are separate.

`SessionCommands` provides prompt and artifact input, steer/follow-up, cancel, approval, model/tools/thinking/task controls, manual compaction, tree navigation and structured plan commands. Queue modes preserve steering precedence. Accepted intent is durable before queue publication; duplicate delivery cannot grant another execution claim. Native snapshots use `fake: false`, decimal wire sequences, distinct journal revision and event watermark, bounded replay and gap/resnapshot semantics. Progress is separately bounded per subscriber; a paused client cannot prevent settlement. `RuntimeCommands` binds create/resume/fork/replace to durable selected-owner and command receipts. Preparation failure keeps the old runtime available; failed drain/selection custody freezes admission for explicit recovery. No process-wide cwd changes occur.

The host restart API pages uncertain commands and tool records. `reconcile_interrupted_call` requires scoped, integrity-checked host inspection that earlier execution ended, then appends one explicit unknown-effect error result without rewriting the original intent. `reconcile_interrupted_command` closes an inspected orphan; inference and new commands stay blocked until the startup barrier clears. Reopened process/job records grant no PID ownership, signals or replay permission. An actual child-process crash after file mutation and before tool outcome is covered by the acceptance suite.

Planning owns readonly policy and prompt selection below the client: draft, correlated questions/answers, accept, execute a step and retain review. Print and controlled modes preserve their source-selected completion behavior. Verification uses full native results, actual command identity/exit and current request-local receipts; echoed commands, zero-test exits, job completion and model claims cannot fabricate a pass. Later mutation or Unknown effects invalidate earlier checks. Concrete browser/native target adapters remain P11.

`subagent` supports explore, research, implement, verify and plan profiles with isolated transcripts, no recursive task tool, parent policy, source-compatible lighter hygiene, generation/token/time budgets, partial output/usage, durable checkpoints and scoped resume. Children share the endpoint queue, and cancellation drains their tools and owned jobs before parent settlement. Readonly execution requires the admitted readonly capability; missing containment never falls back to unrestricted shell execution.

`install_resources` binds a completed P09 catalog and registry to prompt configuration; model/tool changes rebuild it. Optional `NativeExtensions` bind a trusted, admitted helper catalog, install static tools and receive current input, start, context, payload, tool, compaction, tree, lifecycle and resource callbacks. Snapshots distinguish full physical history from active branch and supply current model, thinking, active tools and registered tool metadata. `prepareArguments` runs before native schema coercion/policy/approval. Source-compatible scalar coercion remains intentional. Native custody retains original results before helper projection.

Extension snapshots are bounded to 8 MiB and transferred above the inline threshold in hash-checked chunks. Normal callback/result frames retain their existing bounds. Callback state mutations, provider/process bridges and UI actions use explicit unavailable responses (`DenyBridge`) in this binding; dynamic registrations fail catalog fencing until rebind. P09 broker primitives remain separately available, and P12 owns final client compatibility wiring under D05. Extension code is trusted host-account code, not an OS sandbox. Payload callbacks cannot change selected model/tools/stream/credentials/endpoint; growth must pass native admission. Tree navigation rejects unresolved tool boundaries, and summary plus label commit atomically.

P09 preserves core skill matching, prompt expansion and resource precedence. Native prompt/steer/follow-up accept routed text; P12 owns slash actions, complete skill/template client expansion, CLI/JSONL/SDK facades and UI requests. Source direct steer/followUp do not invoke input hooks; streaming prompt does. Storage lossless/compatible export is available; HTML export presentation remains P12. See `fixtures/runtime/scope.json` for exact compatibility and later-phase boundaries.

Measurements execute release Rust and the pinned TS session with identical file bytes, three fake HTTP requests, one real read and one queued follow-up. The report separates first-request, tool/context, follow-up and total latency, plus 32 cumulative resume/compaction cycles. SQL FULL durability and native original-request/result custody differ from TS JSONL; ratios describe delivered host costs. Heap/RSS observations bound this finite fixture, not 8h/24h or live-model performance. No desktop/model speedup is claimed.

L01–L08 remain binding: preserve each executable/library identity, raw profile precedence, weights/model/request semantics, zero implicit tuning, single endpoint owner, external-process boundaries, originals/rollback and matched quality baselines. The gate rechecks original pins, three tuned backends, libraries, weights, profile bytes and nine launch/six request captures. Live sequential per-model quality, other operating systems, packaging, authority cutover and release duration tests remain their explicit later gates. Rollback stops only owned fixtures, retains uncertain evidence and restores the P09 checkpoint; the normal TS desktop remains usable until P13.
