# Task, memory and evidence services

P07 introduces GUI-independent shadow services. The usable desktop continues to use the TypeScript worker; P10 composes Rust execution and P13 transfers authority. No local model or GPU runtime is launched by these services.

`TaskState` validates task v1 state, preserves objective separately from steering, and implements set/reset/record/update/remove. Eight epistemic kinds retain provenance, confidence and explicit status. Fifty entries and twenty list items remain bounded; blocker, checkpoint and attempt links pin their entries. Imported duplicate identities and malformed snapshots fail visibly. The original import archive remains available in P05 storage. Mutations cannot convert an unsupported claim into a sourced result. A journal `check.passed` is compilation evidence only; later write/edit/bash or failed check invalidates that checkpoint. Source freshness and runtime target revision are independent checks.

`TaskStateService` prepares an exact journal transaction against the selected branch. `PreparedStateCommit` retains its command identity, expected revision and exact bytes so retries settle idempotently. Storage owns the durable commit. A conflicting revision requires reloading and preparing a new command. Call these synchronous ports on the host's bounded blocking executor. `TodoStateService` preserves prospective checklist transitions in separate `todo_list` records. Explicit archive records preserve old plans; plan dialogs, question correlation and mode policy are P10/P12 integration.

`MemoryStore` preserves version 1/2 interpretation, migrates to v3 and retains unknown data. Commands normalize and validate text, kinds, priorities, component sources and duplicate notes. The hot set holds forty entries; displaced normal entries remain archived, while forty core entries require explicit removal before adding another. The bounded shadow catalog supports 10,000 retained memories and 4 MiB documents; exceeding bounds is an error, never silent deletion. Corrupt memory is retained by P05 and blocks ordinary writes. `MemoryService` performs edits through the same durable CAS store.

Selection considers core entries, query overlap, then recent hot entries and restores stable display order. Stale/missing/invalid entries are excluded from unrelated recent filler, but relevant historical entries retain explicit labels. The sixteen-entry cap is hard. The reference's approximately 1,600-character line budget permits one bounded first entry to exceed the soft character budget. It never bypasses the entry cap. UTF-16 text budgets preserve complete Unicode scalar values at a cutoff. Prompt insertion is P08.

`SourceService` uses the P03 root capability, canonical containment, regular-file descriptor reads and before/after identity checks. Raw full bytes determine the SHA-256 before BOM/CRLF display normalization or clipping. `SourceSnapshot` has private fields and validates byte count and hash at construction; display cannot pair independent text and hash reads. Contained symlinks resolve to canonical identities and are rechecked after reading. A host-only mutation barrier forces races in tests. Repeated validation caches parsed references only and rereads bytes: metadata-only hash reuse is deliberately excluded. The read cap is 8 MiB, reference cache 256 and source access history 256. Larger sources fail explicitly.

`InspectionEvidence` records exact read ranges or no-match patterns, flags and source revisions, with a twenty-record deduplicated history. `RuntimeObservation` retains reporter, target revision, environment and reproduction separately from source or build status. RFC3339 timestamps are validated using the already locked chrono dependency. A self-reported agent result is not independent runtime proof. `ObservationRecord` commits these distinct records to the journal. Historical records are never rewritten when validation changes.

`EvidencePort` exposes P05 artifact metadata, byte pages, authenticated cursors, bounded search and leases with an explicit requester session on every operation. Binary metadata and producer provenance survive reopen/fork. A cursor does not grant a stranger access. P11 handles actual native visual capture and request-local attachment; P07 does not claim a runtime observation occurred simply because metadata exists.

The frozen SDK state corpus includes 94 cases. The initial `state-oracle.json` capture is retained for audit; `state-oracle-v2.json` exercises the SDK's persisted-state parser before mutation, matching the Rust input boundary. The initial capture had directly assembled non-normalized entries in memory. No expected Rust output was used to generate either capture.

Measurements use identical private files of 1 KiB, 1 MiB and 8 MiB and the same fifty-entry task state. Warm filesystem cache conditions are recorded. TypeScript's cached validator uses weaker metadata assumptions, so timing differences are not equivalent correctness or desktop speed claims. Linux snapshot/race and durable storage tests are executable here; Windows/macOS/WASM runners and live native/runtime integration remain later gates. Existing llama.cpp binaries, libraries, profiles and weights remain unchanged.
