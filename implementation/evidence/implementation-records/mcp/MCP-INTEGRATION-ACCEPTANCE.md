## Explicit compatibility limits

- Linux native private input and read-only containment are supported. A root-owned, non-writable `/usr/bin/bwrap`, usable user namespaces and compatible system runtime are required. The diagnostic UI harness has an outer user namespace that hides host-root ownership; its contained launch correctly fails. The native UI workflow then explicitly chooses host-account access for its owned peer. Actual confinement is verified separately outside that harness. There is no silent fallback.
- Local runtimes requiring network, writes, unavailable libraries or more than the configured memory/lifetime budget need a compatible configuration or an explicit broader access decision. Working-directory selection alone is never described as containment. Advertised registry package version is provenance, not proof of installed runtime/package contents.
- Guided setup supports exact remote Streamable HTTP targets without custom headers/templates and already-installed local stdio executables. AG1 does not acquire packages. Unsupported recipes/headers/transports/auth configurations use explicit manual guidance. Registry availability/rate limits can prevent fresh activation; cached metadata is not authority.
- OAuth uses public pre-registered client IDs. Dynamic client registration, hosted client metadata documents and confidential-client secrets are unsupported. Logout removes/revokes local custody; upstream revocation is not promised.
- Legacy unsolicited elicitation, free-text/numeric/nested forms, URL elicitation, sampling, roots, subscriptions, protocol tasks, standalone legacy HTTP+SSE and automatic resumption are unsupported/refused. Audio is retained as encoded original content with explicit unsupported playback. Unsupported image formats remain inert original data.
- Child MCP connection inheritance/automatic connection creation is unsupported. This was previously described as unfinished development work; the core project prompt does not require it. Child prompts explicitly route MCP-dependent work back to the parent instead of acquiring its connections or credentials.
- This acceptance uses owned peers and scripted provider responses, not real inference or live accounts. Windows/macOS, minimum Rust-version execution, the separate real-model audit, duration programme and broader P14 release work remain outside this task.

## Resource ceilings

Existing lower native/global limits still apply. Configuration: 128 servers, four active MCP connections, one in-flight operation per connection. Wire: 1 MiB frames, bounded JSON depth/nodes and aggregate operation receive budgets; catalogs: 1,024 entries and 32 pages per capability kind. Selected context: 16 definitions and 64 KiB MCP schemas. Trust: bounded scoped grants, 32 rules per capability, 16 scalar selectors per rule and a 1 MiB manager store. Input: one form/round, eight fields, 16 choices/field, three rounds, 64 KiB envelope, 16 KiB opaque state, 120 seconds maximum. Images: eight decoder attempts, 8 MiB aggregate encoded previews, 16 million source pixels, 32,768 pixels per dimension and a serialized bounded decoder. Discovery: 10 entries/page, 32 cached pages, 900 KiB cache payload, five owner requests/minute and source retry delays. Large output is retained within transport/storage bounds and projected through existing authenticated pages; quota failure never implies complete successful execution.
