The [C2 public pre-registration OAuth checkpoint](../../MCP/authentication/oauth-acceptance.json) is [installed and verified](../../MCP/authentication/oauth-installation.json) as a normal per-user production distribution. Restart AG1 from the application menu to load it. It includes the earlier manual-credential workflows. **Scoped trust and full A–F integration remain unfinished.** The [registration decision](MCP-OAUTH-REGISTRATION.md) defines the supported flow and explicit automatic-registration limitation.

Native OAuth discovery now parses Bearer challenges, discovers protected-resource and OAuth/OIDC authorization metadata, enforces exact resource/issuer identities and requires advertised S256 support for code login. HTTPS requests use bounded bodies/headers, destination policy and pinned DNS, without redirects, ambient credentials or retries. Root resource metadata retains the exact MCP endpoint separately.

The Linux native login coordinator reserves a literal loopback callback listener, builds a fresh state and PKCE challenge and supplies a private authorization URL only to a native browser port. It consumes a validated callback once, checks state/path/Host/issuer including error responses, rejects duplicate parameters, emits static non-reflecting responses, and closes the listener on completion, cancellation or abandonment. Owned tests exercise the browser port. The desktop implementation uses GTK consent/progress dialogs and GIO system-browser launch; the owned native browser workflow and wide/narrow screens have now been verified.

Token exchange and refresh now run through the same native HTTPS policy. The private JSON intake rejects duplicate keys and excessive complexity without constructing ordinary JSON values containing token strings. The vault binding persists the exact MCP endpoint, resource, issuer, token endpoint and public client ID; root resource metadata cannot authorize a sibling MCP endpoint. Token requests carry the bound resource/client, and code exchange includes the original redirect and S256 verifier. Account labels from unsigned tokens are ignored.

Refresh uses a one-use native vault reservation, checks it before send and after response, rotates refresh tokens when supplied and retains the previous token when omitted. Changed refresh scopes are rejected. Failed or abandoned exchanges retire only their own reservation; late cleanup cannot revoke a newer login. Successful private results still require an explicit native commit, and dropping an uncommitted result retires the reservation. No operation replay is introduced.
