AG1 selects the GitHub MCP Registry at `https://api.mcp.github.com/v0.1`. The official registry still directs host applications toward downstream registries, while GitHub explicitly describes compatibility with other MCP hosts. PulseMCP's documented API requires a private tenant/API key, so it was not selected. Sources: [official host-app guidance](https://modelcontextprotocol.io/registry/about), [GitHub's registry announcement](https://github.blog/ai-and-ml/github-copilot/meet-the-github-mcp-registry-the-fastest-way-to-discover-mcp-servers/), [PulseMCP API](https://www.pulsemcp.com/api/docs/v0.1), [v0.1 interface](https://github.com/modelcontextprotocol/registry/blob/main/docs/reference/api/openapi.yaml).

Read-only public observations confirmed list/search/cursor and exact-version responses, with `server` and `_meta` wrappers. Samples and headers are in `.local/mcp-discover/github-*-sample.json`. The observed GitHub headers advertised a five-minute public cache and a request limit of 10; AG1 also limits its owner to five requests/minute and respects bounded rate-limit reset/Retry-After values. No availability/SLA guarantee is inferred. Registry metadata is an upstream assertion, not code authentication or trust. The directory is curated/partial and exposes explicit missing/stale/error states.

Only explicit Search/Refresh fetches metadata; opening Discover reads local cache. User-entered queries never include automatic chat/source/workspace content. Requests use a fixed source, HTTPS, native public-address resolution and DNS pinning, with no ambient credentials, proxy, redirects, automatic retries, icon/README fetches or advertised-server contact. Requests have a 12-second bound, pages a 1 MiB/depth-32/node-20,000 ceiling, ten entries/page, 64 KiB retained entry ceiling, at most 32 cache pages and 900 KiB cache payload. Cache uses an isolated store and failures do not prevent manual server management. Config/provenance fields are retained; bulky publisher README/icon fields are omitted. Renderer text is literal.

Remote setup supports exact HTTPS Streamable HTTP endpoints without URL variables/custom headers. It revalidates the selected version/status/digest, displays an expiring native review, and saves inactive only after confirmation. Registry-derived connection reviews revalidate again; changed or withdrawn metadata and source outages cannot activate from stale cached approval. Manual edits create manual provenance and require the ordinary full launch review.

Local guided setup accepts an already installed stdio executable, literal arguments, reviewed directory and required public environment. Private variable names come from the native listing and their values use the existing native private entry after saving. Initial local access is read-only directory with networking disabled. Package identity/version are displayed as advertised, not falsely verified against the installed code. AG1 does not download packages, install runtimes or run package managers. Other transport/header/template recipes provide manual guidance and retain inspectable metadata. Automatic acquisition and a broader recipe matrix remain future work within the final completion review if required by the task's supported-recipe boundary.
