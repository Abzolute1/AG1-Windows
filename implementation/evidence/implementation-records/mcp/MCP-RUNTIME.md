B4 connects explicitly selected MCP capabilities to the ordinary native session tool loop. This continues [B3 resource and prompt execution](MCP-CONTENT.md). The [accepted source evidence](../../MCP/session-integration.json) records this checkpoint. This is not a desktop installation or full A–F completion.

`SessionCapabilities` is a native-owned port bound to one workspace/account-session owner, session ID and epoch. The host supplies the catalog scope and selected entries; arguments, renderer metadata and peer results cannot construct that authority. Workspace catalog selection must match the native workspace ID. General-chat catalog selection is explicitly bound to the supplied native session owner. Desktop account/project resolution remains a later composition step.

The port sits in `NativeAdapters` and prepares an MCP operation before approval. Preparation reserves the existing one-operation connection slot and validates the complete selected identity. The standard runner then performs policy/approval, acknowledges durable intent, invokes the adapter and persists the terminal tool result. It does not nest another executor. The standalone manager entry uses the same reservation and operation implementation. Dropped/rejected preparation releases its reservation without sending.

A native runtime check reads the actual tool journal's batch cancellation, session/epoch/stamp and revision. An optional shared approval-policy revision is checked too. The connection worker runs that check at send admission, alongside its original catalog/approval/connection gate. The adapter polls the same check while awaiting the bounded worker reply, cancels its owned connection on revocation/deadline, drains the response and suppresses private result projection after revocation. Admitted operations retain effect uncertainty. MCP results carry native identity in their source metadata and retain originals through the existing context artifact port.

Each outgoing request derives its MCP definitions from the native registry, removes unavailable or foreign-session selections, and rechecks them after asynchronous provider preparation and scheduler admission. A changed unsent request is discarded and rebuilt. Tool execution and XML fallback use the schemas actually admitted for that generation. This does not populate the model context with the full connected catalog. An owned 1,000-tool server contributes one selected schema below 4 KiB in the native model-loop fixture.

## Verification and limits

Six owned native-loop contracts exercise tools, resources and prompts; both transports; exact source/artifact custody; general bypass still requiring MCP approval; foreign owner/session/epoch and planning refusal; single-worker cancellation before and after send; and disable during queued provider preparation. Fixed scripted model responses are used, not real inference. Existing service execution contracts continue to exercise both supported protocol revisions and replay/storage faults.

The final selected suite has **211 passing tests**, including all six new runtime contracts. The broader session suite has **243 passes and 16 failures on both the candidate and isolated B3 source**, with identical assertion bodies after normalizing only thread IDs and the once-per-process backtrace-help line. The baseline uses the same owned extension runtime/toolchain and fixture inputs. No test expectation was changed. An additional HTTP-fixture failure in the initial candidate run did not recur in either final run; no root cause is claimed. The initially incomplete baseline fixture setup and a misdirected diagnostic log are retained separately and excluded from acceptance.

Clippy succeeds with the same 63 existing platform warnings and no new MCP runtime diagnostics. Formatting checks cover the new modules and MCP files; existing session files retain their prior formatting. All previously accepted binaries, Cargo.lock, core/storage/protocol logic, installed files and model configuration are preserved. The session adapter source, protected by earlier service-only checkpoints, necessarily changes for this authorized integration; its exact prior bytes remain in the [preserved baseline archive](../../../../.local/mcp-b4/before/product/crates/ag1-platform/src/session/adapters.rs), and the [source change record](../../MCP/runtime/authorized-source-changes.json) makes that exception explicit.

Still required: dynamic model-driven discovery and selection, canonical desktop account/project composition and lifecycle, context eviction/admission witnesses for changing selections, OAuth/private configuration and trust grants, media rendering, manager UI, public discovery/setup, supported input continuation, full protocol/conformance/resource budgets, and production acceptance/install. Native session ports are currently host-wired explicitly in owned fixtures; the shipped application factory does not yet construct them. Other feature tasks, real-model tests and the duration programme remain paused.
