# MCP input continuation — development, 2026-09-12

> Historical evidence, archived 2026-09-13. Status, commands, permissions and paths below describe their original checkpoint. For current work start with [implementation status](../../../README.md). Original bytes and old paths are preserved in the [relocation manifest](../manifest.json) and recovery archive.

Current-protocol input forms now continue an already admitted operation through the same owned transport, native send gate, credential/catalog/policy identity checks and durable original intent. Input requests use new correlated JSON-RPC IDs while preserving the original method and arguments. There is no transport retry/replay after uncertainty. This development batch is not production-installed; physical native UI and combined regression checks remain deferred until the implementation is complete.

Supported forms are one `elicitation/create` request per round, with up to eight top-level boolean or explicit string-choice fields. Unknown schema constraints are refused rather than dropped. At most three rounds, 64 KiB per input envelope, 16 KiB opaque request state and 120 seconds for the entire interactive operation are allowed; the native task deadline can cancel sooner. Discovery requests never advertise/accept forms. Free text/numbers/nesting, URL-mode authentication, sampling, roots and state-only retries remain explicitly unsupported. Legacy unsolicited requests retain their existing protocol refusal.

The GTK dialog displays exact native server/capability/call/scope identity, original arguments and literal server questions. It supports required/optional choices, explicit reviewed-answer acknowledgment, decline and cancel. There is no free-text credential entry. Opaque state never enters the dialog/renderer, model context or retained result artifacts; native transport alone echoes it to the same waiting operation. Supplied private-value echoes are rejected before presenting an intermediate form. Revocation, cancellation and credential/identity changes reject the next send. Catalog metadata is refreshed and matched again between continuations. The manager exposes waiting-for-input state separately from connection health.

Native session adapters derive interactive permission from the actual execution policy; planning and headless modes never enable form input. The standalone executor defaults to no interactive input and has a native-only explicit interactive opt-in. The native entry port is composed before connections are created, independently of renderer/server data.

Checks confirm one durable original intent, preserved original arguments, distinct protocol IDs, no unexpected follow-up after cancel/revoke, and no opaque state in model results/native form projections. Final completed replies use the existing original-result retention path; interrupted operations retain their original intent and unknown-effect outcome.
