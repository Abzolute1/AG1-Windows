# MCP media/result presentation — development

> Historical evidence, archived 2026-09-13. Status, commands, permissions and paths below describe their original checkpoint. For current work start with [implementation status](../../../README.md). Original bytes and old paths are preserved in the [relocation manifest](../manifest.json) and recovery archive.

MCP tool, resource and prompt results now project supported images through the existing native bounded decoder. PNG/JPEG/GIF/WebP MIME must match the actual header. Images are decoded, orientation-applied and rasterized into a bounded PNG/JPEG preview; source metadata and animation are not sent to the renderer. SVG and other unsupported formats remain inert in retained original JSON. Limits are eight decoder attempts per result, 8 MiB aggregate encoded previews, 16 million source pixels, 32,768 pixels per dimension and the shared decoder allocation/serialization limits. Oversized, malformed and unsupported previews have explicit reasons. Ordered text/image projections and full original MCP response custody remain separate.

The ordinary authenticated journal image route supplies chat previews. MCP images identify their originating capability and label themselves as raster previews. Native message projections provide server/capability identity, literal resource cards, and an explicit original-response inspector using the existing requester-authorized artifact paging/download route. Resource references never navigate or fetch automatically. Media after the first eight compact message blocks still has a journal attachment reference; loading full text preserves the native source card. Audio remains retained encoded content with an explicit playback limitation; the core prompt's image presentation requirement is implemented. Original JSON can be inspected, copied by page and downloaded through the existing output surface.

Focused evidence: `.local/mcp-media/workflow-rust.log` passes twelve media scenarios across stdio/HTTP (valid raster, embedded image, count limit, MIME mismatch, malformed input and pixel bomb). The final input opt-in API also compiles and its ten continuation scenarios pass in `.local/mcp-input/standalone-opt-in-rust.log`. Two new UI tests pass for inert resource cards, lazy authorized original reads and correctly labelled image previews. Six existing image UI checks pass; one existing fixture still expects the old `Activity 1 file read` label although the installed work summary uses `Work details 1 tool`. Its expectation was preserved. This is not final combined acceptance or a production installation.

Requirement clarification: child MCP connection inheritance was previously listed as unfinished development work. The core project prompt requires scope/session isolation and the existing scheduler, but does not require MCP authority to transfer to child agents. Current child sessions deliberately receive no MCP adapters; their native prompt now explicitly directs MCP-dependent work back to the parent. Automatic child connection creation/delegated MCP access remains unsupported and is not claimed implemented. This limitation must appear in final compatibility/acceptance rather than silently enlarging the core completion boundary.
