B5 adds model-driven discovery and changing selections to the [B4 native session bridge](MCP-RUNTIME.md). The [accepted source evidence](../../MCP/model-discovery.json) records this bounded runtime checkpoint. Full A–F integration remains active; the desktop factory and UI do not yet expose these ports.

The native `mcpDiscover` facade searches already connected, scope-filtered metadata, inspects an admitted capability schema, replaces the current selection, reports status, or clears it. It cannot connect a server, resolve credentials, read a resource, obtain a prompt, choose a protocol method, supply continuation state, or approve an external operation. Only this native-host origin receives the metadata policy exemption; a same-named extension does not. Actual MCP calls retain their separate native identity, ordinary executor, durable intent and explicit unknown-risk approval.

A selection belongs to one native workspace/account-session owner, session and epoch. Each model request captures an immutable registry and selection-generation witness. The next request receives at most 16 selected capabilities and 64 KiB of selected metadata, alongside the small native discovery facade. Selecting a capability does not admit an unadvertised call in the current assistant batch. A selection change invalidates unsent requests and old approved operations; runtime send/delivery checks also carry its generation witness. Rejected selection changes publish nothing. Revoked catalog selections are cleared without silently adopting changed metadata.

The captured prompt registry accepts a typed native MCP overlay and still checks exact tool descriptions and schemas. Other captured tools and resource instructions keep their original authority. Native mode controllers can further restrict a request without the MCP layer putting those tools back. Clearing drops selected schemas from later requests while retaining source-correlated historical tool results and artifacts. Selections are ephemeral and a fresh session port starts empty.

## Verification

Eight new contracts cover native discovery and the typed prompt/policy boundaries. Owned scripted model loops exercise tools, resources, templates and prompts over stdio and Streamable HTTP, including a 1,000-tool catalog. Outgoing requests contain only the facade until selection, then the facade plus one selected schema (below 8 KiB together), and return to the facade after clearing. Other contracts check same-batch smuggling, foreign scope, atomic refusal, changed selection during provider preparation and during exact approval, forged metadata and schema eviction.

The final selected suite has **219 passing tests**. The candidate has **243 passes/16 existing session failures**; both full isolated B4 baseline runs have **242 passes/17 failures**. Every candidate failure has an identical baseline assertion body after normalizing only thread IDs and the once-per-process backtrace-help line. The extra baseline-only extension fixture fails with a provider HTTP connection error in the full suite and passes when run alone. That variability remains unresolved; both full logs and the exact recheck are retained, and no root cause is claimed. The core comparison is identical at **22 passes/6 existing failures**. No frozen expectation changed. Clippy passes with the same 63 existing platform warnings and no new discovery diagnostics. Accepted binaries, storage/protocol logic, fixtures and Cargo.lock are preserved; final candidate and baseline binaries have distinct immutable profiles. No installation was performed.
