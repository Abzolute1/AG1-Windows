# Captured context and retrieval (P08)

These Rust services run in isolated shadow destinations. The desktop still executes the preserved TypeScript SDK. P10 must connect them to branch epochs, cancellation, the one P06 scheduler and the final model-admission barrier before P13 authority transfer.

`ContextSnapshot::capture(Vec<Value>)` takes ownership of an explicitly captured branch, validates its 100000-message/128 MiB limit and records token estimates on private immutable messages. `compile_snapshot` shares unchanged messages, returns the selected snapshot plus budgets/reduction/over-target statistics, and refreshes artifact reads and current leases on every call. `compile_request` is an owned-JSON compatibility wrapper. Cache reuse applies to immutable captured bytes only; it confers no file freshness or artifact authorization.

The compiler preserves ratio .62, 48k/160k caps, low water .78, three protected assistant turns, bounded evidence leases, tool payload/result externalization, exact salient lines, metadata eviction and complete protocol rounds. Typed cursors, leases and segmented catalogs default on with explicit captured environment overrides. Protected evidence may remain over target; this is reported, not removed to manufacture a successful budget.

`ag1_storage::context::ContextStore::project` retains the exact raw journal/header as base64 and the explicit request as immutable P05 artifacts before invoking a reduction. It checks the expected journal revision before and after, rejects orphan results, and returns custody records and revision. Artifact writes preserve producer and parent-entry provenance and acknowledge blob/directory sync plus SQLite commit. A failure or ambiguous acknowledgement returns no projection; retained orphans are recoverable on restart. This is a shadow transaction receipt, not permission to admit a stale request. The final actor must fence admission again in P10.

`retrieval::retrieve` consumes explicit source, lexical, changed-file, recent-access and cancellation ports. `ag1_platform::retrieval::SourceHost` runs an owned bounded `rg` process or an explicit bounded CPU fallback. Source bytes come from P07's validated one-read snapshots. Explicit paths, exact symbols, vague follow-ups and changed-line recovery have independent required/forbidden fixtures. Candidate ordering, score, ranges, clipping, source references, symbols and relationships match the frozen SDK. Git state and recent-access parsers consume captures; the caller supplies current workspace state. No embedding, reranker or filesystem metadata shortcut is involved.

Capsules retain body hashes, artifact IDs, file/range references and reconstruction status. Missing artifacts do not become recoverable because a matching capsule ID exists. Capsule display paths must match their source-reference paths; this intentionally rejects forged labels. Source health never rewrites a historical body. Host retrieval explicitly sorts `rg` paths for deterministic ties.

Episodes have explicit begin/close journal commands with CAS. Closing retains the selected original trajectory bytes before appending the episode index. Retrieval can search older closed episodes, detects contradictory stable claims and produces at most three automatic pointers within 2400 UTF-16 units. Health includes trajectory/artifact availability and source verdicts; a historical claim cannot acquire verification from its index alone.

`episode_draft::prepare` stores original trajectory bytes before budgeting the analysis input. It externalizes bulky outputs, preserves protected user/recent evidence, and fails visibly when that protected input exceeds the budget. Its request is bound to the selected provider, endpoint, model and runtime fingerprint. `finish` checks that scope again, retains raw model output and parses a non-authoritative candidate against the allowed source catalog. Summary and draft requests use P06's isolated one-user-message/no-tool contract. They must execute sequentially using the existing scheduler permit; these services create no model client, process or second scheduler.

Prompt construction takes captured time, workspace resources, tools, capabilities and mode inputs. Prefix hashes use canonical tool schemas. Per-turn task, checklist, memory, observation, episode and runtime addenda preserve ordering and warnings. Checklist declarations do not prove completion. Source-derived knowledge requires current validation; inferred prose verification in working memory is explicitly historical.

Compaction supplies exact SDK horizon calculations, pinned request, cut/preparation fields, working-memory ledgers, initial/update/split prompts and deterministic fallback. Pair-boundary correction may keep more history than the legacy cut. Hygiene and retry functions return projections and never overwrite a journal. The legacy prompt-too-long head-drop helper is for stateless analysis input; use custody plus separately retained pinned/task state and complete-pair checks when composing runtime recovery. P10 still owns pending suffix transformation, retry limits, summary commits and latest-epoch admission.

Eleven executable SDK probes cover 16 cold/warm compiler histories, source retrieval, episodes, prompts, state/addenda, recent/Git signals, full compaction preparation, actual fixture-provider summary/draft calls and emergency retry transforms. Raw evidence, order, claim kinds, full prompts and hashes remain exact. Random IDs/clocks alone are normalized; JavaScript undefined fields disappear only at the JSON persistence boundary. RFC3339 date validation and Unicode scalar-preserving clipping are explicit boundary constraints.

`python3 tools/reference_oracles.py --suite context-differential --offline` compares the frozen captures and runs the three Rust context contracts. `python3 tools/phase_gate.py P08` additionally runs earlier state/storage/provider regressions, strict lint/format, failure-rejecting gate tests and runtime preservation checks. Measurements separately report cold capture, warm projection, allocator requests, durable custody, integrity-checked reopen and complete rehydration. Volatile callbacks are compared only with equivalent volatile callbacks; P05 fsync/WAL rows are not compared against unsynced SDK storage. No desktop footprint, GPU or live-model claim follows from these synthetic tests.

The existing three tuned llama.cpp backends, library selections, weights, arguments and request semantics remain unchanged. Windows/macOS, live provider quality, native UI integration and 8h/24h release acceptance remain later gates.
