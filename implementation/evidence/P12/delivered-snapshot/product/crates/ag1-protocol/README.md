# Protocol v1 contract

Rust DTOs in `src/wire.rs` are authoritative. JSON Schema is generated with pinned Schemars 1.2.2 and TypeScript with ts-rs 12.0.1. All direct versions and the transitive graph are locked. Selection was validated by compiling and round-tripping tagged unions, every error variant, required nullable fields, absent versus explicit-null custom extensions, and decimal sequences above 2^53 through Rust, TypeScript and Ajv. The tools' APIs are documented at [Schemars](https://docs.rs/schemars/1.2.2/schemars/) and [ts-rs](https://docs.rs/ts-rs/12.0.1/ts_rs/). License texts, including the ts-rs repository license missing from its published crate, are recorded under `../../licenses/`.

```sh
cargo run --manifest-path product/Cargo.toml -p ag1-protocol --bin protocol-codegen
cargo run --manifest-path product/Cargo.toml -p ag1-protocol --bin protocol-codegen -- --check
```

Generation deliberately runs as an explicit command. Normal builds/tests never rewrite generated output. Commit/review the Rust source, schema, generated TS and codec fixtures together. Schema mismatch or incompatible major version rejects negotiation; matching schemas negotiate the supported minor version. `Version.schema` is the SHA-256 of compact generated schema JSON. Future additive schema negotiation needs an explicit compatibility table; unknown schemas fail closed today.

Every command carries its own ID and workspace/session/instance/epoch scope plus expected revision. Results retain the command ID, scope and event watermark. Admission is separate from completion. Repeating an identical accepted envelope returns its prior admission even after revision changes; reusing its ID with different contents conflicts. Query `command_result` to retrieve terminal status. The fake records are bounded and retained for that instance; it refuses new work rather than evicting an idempotency key. This does not promise exactly-once external effects. P05 must supply transactional intent/results and interrupted-outcome recovery before any real execution uses this contract.

`subscribe()` registers a listener and returns a snapshot at one `&mut` owner barrier. Durable-style fixture events after that watermark are replayable in pages of at most 32. Clients track their own last applied cursor and may call `replay()` after a lost delivery. Polling alone is not a client acknowledgement. A cursor older than retained history, ahead of the host, or from another instance/epoch returns `Gap` with a fresh snapshot. A client projection rejects out-of-order events and late old-instance events; duplicate already-applied events do not mutate state. Only a fresh snapshot clears a detected ordering gap.

The normal wire ceiling is 64 KiB. Session admission allows 256 queued operations and endpoint waiting rooms allow 128 requests. Binary artifact reads return base64 for at most 32 KiB of original bytes, keeping worst-case pages inside the JSON envelope ceiling. Large prompts use a scoped artifact reference; fixture setup installs bytes directly and is not an upload transport. A real authorized upload API belongs to the adapters.

Each of at most 64 subscribers holds at most 1 MiB of encoded transient frames. Overflow discards coalescible progress and sets an explicit gap. Terminal operation results remain in the host; stale progress is not emitted after terminal recovery. A snapshot contains queued IDs and the last terminal view, and individual command-result reads recover other outcomes. Retained events cap at 1,024. The fake stores at most 4,096 command records (new prompt admissions stop 512 slots earlier to reserve approval/cancellation capacity), 256 fixture artifacts and 8 MiB of fixture bytes. These are fixture limits, not a replacement for future durable storage. Slow clients never control event history retention.

Approvals are issued by the fixture host and bind a registered operation, argument SHA-256, full scope, revision and expiry on the deterministic clock. Matching only an operation ID is insufficient. An approval blocks fixture scheduling; rejection/cancellation settles the operation. Repeating the same command ID returns its prior response; a second answer with a new command ID rejects a consumed binding. A changed revision or expired binding remains blocked until cancellation or a later explicit reauthorization implementation. Production authorization must derive hashes from immutable admitted arguments; fixture setup is not a renderer API.

All u64 sequences, epochs, revisions, offsets and clock values use canonical decimal strings. Rust checks the complete u64 range. JSON Schema checks spelling and a 20-character ceiling; a frontend must still enforce the u64 upper bound before using BigInt. Strong Rust ID constructors validate bounded ASCII tokens; generated TypeScript aliases are strings and require boundary validation. `extension` preserves opaque JSON, including explicit null versus absence. Required nullable fields must exist even when null. Rust's strict field parsing and fixture/schema tests cover Serde attributes not interpreted by ts-rs; its unsupported-attribute warnings are disabled intentionally.

The fake host makes no filesystem, process, model, network or persistence calls. Restart discards its in-memory state, requires a new instance, advances epoch and rejects stale traffic. Its namespace and `fake: true` handshake/snapshots prevent representing it as a real agent. These tests establish protocol semantics; P03/P04 add native services and transports, P05 adds storage, and P06/P13 establish preserved model runtime behavior and ownership.

P10 now supplies `ag1_platform::session::commands::SessionCommands` for native prompt admission/execution, result queries, authorized artifact pages, snapshots and bounded replay. It captures one registry selection and uses `fake: false`. The facade also supports cancellation, approvals, current configuration/task controls, steering/follow-up, compaction, tree and planning commands; RuntimeCommands binds durable session lifecycle changes. Unbound target/client command families report explicit unavailable status (see ag1-platform/SESSION.md). The TypeScript desktop remains the production authority.

Native operation-event sequence is independent of both SQL global sequence and session journal revision. Admission can leave journal revision unchanged; one completed turn can advance it by many records. Native clients use `projection::Projection`, which checks contiguous event sequence and nondecreasing journal revision. `fake::Projection` retains the fixture's stricter one-event/one-revision assumption. Native read queries validate full scope but do not require the caller's journal revision to remain current: reconnect/result recovery must work while the journal advances. Mutating prompt admission still checks expected revision transactionally. Event history resets with the host instance; durable per-command results survive restart, and incomplete intent never grants automatic execution.


The native P10 facade also exposes subscriptions and transient text progress. Registration captures the snapshot and cursor together; at most 64 subscribers each retain at most 1 MiB of encoded progress. Polling returns operation events before transient frames, uses the same 32-event replay bound, reports overflow/history gaps and drops stale progress after terminal recovery. Native provider text deltas are relayed independently of external listener success. A delta too large for v1, or a content replacement that v1 progress cannot represent, requests resynchronization; it does not truncate the durable final message.
