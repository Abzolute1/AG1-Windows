# AG1 capability parity matrix

This is the capability ledger for the pinned revision, not a claim of implemented Rust parity. Prefixes resolve exactly as specified in README: `A:` coding-agent `src/`, `G:` agent `src/`, `M:` ai `src/`, `T:` coding-agent `test/`. Test names without a directory prefix are under `T:`. All rows must be assigned to roadmap phases or explicitly retained as adjacent/legacy/unintegrated scope; none may silently disappear.

Difficulty: L = contained, M = several owners, H = semantic/concurrency/data risk. Dependency labels refer to work packages in DEPENDENCY_GRAPH, **not predetermined phase numbers**: E evidence/oracles, P protocol, S storage, O OS/process, V providers/scheduling, C context/evidence, R runtime/tools, U UI, N native project runtime, X compatibility/packaging. Current tests are parity oracles where applicable; newly required tests are labeled “new”. Existing test paths do not imply they were all run.

## Coverage and disposition rules

This matrix covers the active desktop-relevant harness plus separately shipped packages and discovered unintegrated paths. A roadmap must split rows further where independently testable behavior would otherwise be hidden (for example provider families, each mutation tool and each persistence format). That refinement must preserve these IDs as parents. It must not convert “partial” into “active” based on exports or comments, or drop an adjacent API without an explicit compatibility disposition.

No general cross-platform performance, GPU runtime, remote-provider parity or new frontend behavior has been proved. Every H row needs a concrete trace fixture and failure fixture before its TypeScript authority is retired. Corrected defects B01–B04 use the documented intended invariant as oracle, not the defective old output.
