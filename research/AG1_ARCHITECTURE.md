# AG1 architecture at the inspected revision

Paths and status terminology follow [README](README.md). AG1 is a TypeScript monorepo with an independent low-level loop and a much richer coding-session harness. Porting `packages/agent` alone would lose most of what makes AG1 effective.

## Entrypoints and ownership

| Owner | Exact path / anchor | Responsibility |
|---|---|---|
| CLI | `packages/coding-agent/src/cli.ts`, `main.ts:main` | Argument/config/package commands, resource/model startup, service/runtime construction, interactive/print/JSON/RPC selection |
| Construction | `A:core/agent-session-services.ts`, `A:core/sdk.ts:createAgentSession` | cwd-bound settings/resources/auth/model registry; restore messages; construct Agent and AgentSession |
| Runtime host | `A:core/agent-session-runtime.ts:AgentSessionRuntime` | Prepare replacement session before cutover; new/resume/fork/import; teardown; currently changes process cwd |
| Session | `A:core/agent-session.ts:AgentSession` | Tool registry/hooks, live request context, task/CV/artifacts, event serialization, recovery and public facade |
| Loop | `G:agent.ts:Agent`, `G:agent-loop.ts:runLoop` | Messages, steering/follow-up queues, stream execution, tool rounds, abort and terminal events |
| Providers | `M:api-registry.ts`, `M:stream.ts`, `M:providers/register-builtins.ts` | API dispatch and provider adapters; normalized streaming messages/usage |
| Clients | `A:modes/interactive/interactive-mode.ts`, `A:modes/print-mode.ts`, `A:modes/rpc/rpc-mode.ts` | Presentation plus some still mode-owned execution policy |
| Native host | `packages/godot-agent-runtime/src/main.ts`, `session/godot-agent-session.ts` | Real headless embedding with versioned handshake, host tool requests and native observations |

`AgentSession` owns an artifact store rooted at `<sessionDir>/artifacts/<sessionId>` (temporary root for in-memory sessions). It owns request-local projections, source validation caches and coordinators. `SessionManager` owns the branch journal. Tools write typed custom records through that journal. Settings/resources belong to cwd-bound services; model provider registration and inference pools still include process globals.

## End-to-end turn

1. CLI builds services and an `AgentSessionRuntime`; SDK callers can construct a session directly. `sdk.ts` restores the branch's model/thinking/messages and installs conversion, provider transport, context and extension hooks. Default tools are much broader than the stale SDK comment saying four coding tools.
2. Interactive, print and RPC modes call `buildTurnSystemPromptAddendum` in `A:core/turn-addenda.ts`: memory selection, optional orientation/Git, finished jobs, caller todo/runtime guidance and verifier contract. A bare SDK caller does not automatically get every mode-owned addendum/completion behavior.
3. `AgentSessionPromptCoordinator` expands templates/skills and prompts, validates auth/model, queues steering/follow-ups and prepares turn state. Session-owned task instruction capture retains the original objective and latest user instruction separately.
4. `Agent` runs the loop with a message snapshot. Before **every** model request, `AgentSession`'s `prepareContext` drains queued persistence and compaction, captures missing legacy task objectives, validates source evidence, builds the current working state and compiles the live `agent.state.messages`.
5. `_checkLiveContext` checks the actual upcoming request with a 10% estimate margin. If compaction changes epoch, branch leaf, messages, tools or system prompt, the request is rebuilt. Returning the authoritative transcript replaces the loop's earlier snapshot. This interaction is essential: merely compacting a UI/store copy has no effect on a running tool loop.
6. Request-local task, runtime observation, inspection, plan and episode pointers are inserted by `_installCacheFriendlyWorkingStateTransform`. The mutable working state is kept out of the stable system prefix. Extensions transform context; `sdk.ts` applies provider working-set conversion and image blocking, then `convertToLlm` maps custom harness messages into provider messages. Audit/prefix-shape attribution runs here.
7. `createResilientStreamFn` resolves auth and enters the shared inference scheduler; provider adapters stream text, reasoning, tool argument fragments and usage. Loop-level TTFT/idle guards and repetition detection supervise the stream. Native/compatibility tool formats remain provider-specific at the adapter boundary.
8. Tools undergo argument preparation, schema validation, before-call policy/extension checks and execution. Parallel calls are preflighted in source order, launched concurrently, then finalized in assistant order; per-file mutation queues serialize conflicting built-in writes. Controlled policy can instead demand a single action. Malformed/truncated calls are not executed.
9. After-call hooks capture observations, research/delegation evidence, outcomes, repeated failures and large results as immutable artifacts. The `artifact` tool is exempt from recursive artifact-of-artifact capture. Every accepted tool call has a corresponding result, including abort/error outcomes.
10. `AgentSessionEventLoopCoordinator` serializes events, persistence and turn-boundary recovery. Pending tool IDs prevent compaction halfway through a tool batch. Duplicate ends do not resurrect pending IDs. Public events currently precede the corresponding message append; a future UI must not mistake an event for a durable commit acknowledgment.
11. The loop continues for tool calls or steering, then consumes follow-ups before ending. Recovery may continue after `agent_end`; callers use session completion/drain methods. Print mode additionally enforces coding-completion evidence. UI idle, loop terminal and settled session are distinct boundaries.

## Context and CV

`A:core/context-compiler.ts:compileContextWorkingSet` is active by default. It uses deterministic token estimates, not an LLM summary. Default working ratio is 0.62; cap 48,000 tokens, or 160,000 for windows at least 200,000; pressure targets a 0.78 low-water ratio. Three recent assistant turns and associated handoff evidence are protected. Fixed system/tools/request-tail costs count toward the budget. It externalizes older large call payloads and results, compacts previews, strips eligible historical thinking under pressure, evicts reloadable artifact metadata, then prunes complete catalog tool rounds. Evidence leases can protect up to 10% of the target budget. It returns `overTargetTokens` when protected/fixed state cannot fit; a target is not a guarantee.

`A:core/cv-architecture.ts:resolveContextArchitectureFeatures` defaults typed evidence cursors, evidence leases and segmented artifact catalog **on**. Explicit SDK options and `AG1_CV_ARCHITECTURE`, `AG1_CV_TYPED_CURSORS`, `AG1_CV_EVIDENCE_LEASES`, `AG1_CV_SEGMENTED_CATALOG` can disable them. The SDK's “all default off” comment is obsolete. Direct `ArtifactStore` construction has its own feature options; do not assume an isolated constructor has session defaults.

`A:core/agent-session-compaction-coordinator.ts` still runs manual/automatic LLM summarization. It externalizes the original trajectory, preserves provenance, commits a compaction journal entry, merges pending suffix messages, increments epoch and schedules continuation. Summary calls have a deadline; extension failure falls back to built-in handling. `compaction/micro-compact.ts`, `snip.ts`, `strategy.ts`, `working-memory.ts`, `branch-summarization.ts` and `ptl-retry.ts` support provider hygiene, emergency fallback or branch summaries. They are not all obsolete just because the compiler exists. `compaction/horizon.ts` is exported/tested but not an independently traced production scheduler.

No embedding/vector retrieval, learned reranker, general arena/allocator GC, or independent delta-context wire protocol was found in the active CV path. Lexical ranking and prefix-stable request projections are active. Metadata eviction is not deletion of immutable evidence. General text-artifact GC is not demonstrated; binary retention has its own policy.

## Retrieval and provenance

`A:core/tools/source-context.ts:createSourceContextToolDefinition` exposes build/list/validate operations. It combines explicit contained paths, ripgrep lexical matches (bounded workspace-index fallback), regex symbol extraction from `code-intelligence.ts`, recent accesses from the branch and Git changed-file/line signals. Explicit paths dominate; vague queries can recover through the last two accessed files and, when no lexical match exists, up to four changed paths. Ties sort by path. Source relationships are bounded imports/references over selected files, not an LSP semantic graph.

Capsules include exact displayed ranges, canonical `file:<relative-path>@sha256:<digest>` references, symbols, relationships, truncation markers and an immutable artifact ID. Long lines can be explicitly clipped; “exact source capsule” does not imply full-file fidelity. `context-capsule.ts` stores version-1 records in custom branch entries, caps files/ranges/symbols/relations and derives current/stale/missing/invalid status from source and artifact health.

`source-revision.ts` resolves real paths within the workspace, hashes regular files, rejects unsafe paths and caches validation by device/inode/size/mtime/ctime. External editor and shell changes therefore invalidate without tool hooks. Git HEAD alone is never sufficient freshness evidence. A confirmed race between the separate text read and revision read is documented as B03; fix that race without weakening canonical provenance.

`source-retrieval-signals.ts`, `repo-map.ts` and `workspace-index.ts` provide Git status/diff, recent accesses, manifest/scripts/tests/import summaries and process-local caching. Retrieval is usually explicitly tool-driven; the compiler budgets/externalizes its results rather than silently running a semantic search on every request. Episode pointers are a separate automatic request-tail path.

## Task, plan, verification and memory

`task-state.ts` stores version-1 snapshots in `task_state` journal entries: objective, latest instruction, phase, status, lists and epistemic entries. Kinds include FACT, OBSERVATION, HYPOTHESIS, DECISION, CONSTRAINT, ASSUMPTION, RESULT and FAILURE. Status/confidence/provenance remain explicit; caps are 50 entries, 20 list items and a 6,000-character addendum. Transactions are serialized per session owner. `captureTaskInstruction` updates latest instruction without casually replacing the objective. `tools/task-state.ts` validates mutation semantics.

`todos.ts` is distinct from epistemic task state. `tools/submit-plan.ts`, `runtime-observations.ts`, `inspection-evidence.ts`, `delegation-evidence.ts`, `tool-outcome-digests.ts` and task plan formatting preserve declared steps, user approvals/questions, native runtime evidence and verification links. `hasRecordedPassingCheck` recognizes a narrow compilation checkpoint, invalidated by later write/edit/bash/check; it is not proof of every runtime requirement. Print-mode `coding-completion-gate.ts` and optional `ToolOrchestrator` add further gates.

Project memory is `.ag1/memory.json` (`memory-store.ts`), schema v3 with v1/v2 migration, decision/style/breakage/fact kinds, core/normal priority, optional component and source references. Hot set cap is 40, text cap 400; displaced normal entries move to an archive, not silent deletion. Injection is deterministic, typically at most 16 entries/1,600 characters: core priority, lexical relevance, then recent non-stale normal entries, stable final ID ordering. Core priority does **not** override all injection caps despite comments saying always injected. Relevant stale memories are explicitly labeled; recent stale filler is skipped. Global general-purpose memory is not established. Subagent tool profiles determine whether project memory can be written.

`episode-memory.ts` implements explicit begin/close, exact trajectory artifacts and bounded provenance-bearing claims. `episode-candidate.ts` optionally requests an isolated same-model, tool-free candidate; candidates are not authoritative and do not close episodes automatically. `episode-retrieval.ts` scans/ranks historical episode indexes deterministically, validates freshness/conflicts and builds up to three request pointers within 2,400 characters. The episode tool's claim that nothing is automatically injected is stale relative to `AgentSession`'s pointer insertion. Full trajectory rehydration remains explicit.

## Artifact storage

`artifact-store.ts:ArtifactStore` stores content-addressed SHA-256 blobs, immutable `art_<32 hex>` records, lexical indexes and optional segmented catalogs. Record identity is separate from blob deduplication. Text reads use bounded byte offsets (default tool pages and cursor pages differ; store maximum 32 KiB). Cursor encoding authenticates artifact/session/store context, offsets and integrity; preserve opaque bytes across transport. Evidence leases persist bounded protection with expiry and verification-scoped release (16 entries; default two hours, maximum 24 hours).

Binary artifacts are supported, particularly Godot visual evidence: 8 MiB per binary artifact and retained visual bounds of 32 artifacts/128 MiB. `readBinary` verifies integrity; session visual rehydration attaches only capability-eligible, explicitly selected images to the active model, otherwise leaves references. Text search uses lexical indexes and deterministic ordering. Catalog manifests/segments contain integrity and recovery machinery; records/blobs remain authoritative for reconstruction. Some metadata writes use temp/rename, others exclusive writes; universal power-loss durability is not proven.

## Scheduling, subagents and local models

`inference-scheduler.ts` has process-global FIFO semaphores: local depth 1, remote depth 3. Streams hold slots until terminal results, not until stream construction returns. Aborted waiters are removed; an active transport ignoring cancellation releases its slot after a five-second grace. This preserves liveness but cannot prove the old server generation stopped. Pool reconfiguration is documented for idle use only; there are no per-project priorities, bounded admission queues or endpoint-keyed pools.

`tools/task.ts`, `tools/explore.ts` and `subagent-runner.ts` run explore/research/implement/verify/plan profiles in fresh Agents with isolated transcripts and bounded turns/time/tokens. Read-only sets are constructed explicitly and exclude recursive task spawning. Implement/plan retain the parent model; other profiles may route cheaper through `model-routing.ts`. Returned summaries include evidence, usage and partial/failure state. `checkpoint-manager.ts` persists intermediate subagent progress. Parallel task batches still serialize local model requests through the same scheduler. Subagents use lower-level Agent/provider hygiene rather than full parent AgentSession CV: important parity asymmetry.

`llamacpp-runtime.ts` discovers GGUF/split files, model/projector pairs, binaries and model-specific profiles; builds context/cache/GPU/MoE/speculation/slot parameters; probes `/health` and `/props` identity; reuses only compatible running configurations; launches detached with file logs and a runtime state record. It supports eject/switch, readiness waits, cached VRAM profiles and a bounded tuning restart. `AgentSession`/model coordination can ensure managed runtime health before prompts. It is not a continuously running general process supervisor. Port eviction and raw persisted-PID ownership are risks, not behavior to preserve blindly.

`model-registry.ts`, `auth-storage.ts`, capability/thinking/vision modules, LM Studio settings and local inference classification coexist with multiple remote APIs. OAuth/auth refresh and compatibility transforms must not disappear in a llama-only first port. `nvidia-stream-fallback.ts` adds an NVIDIA-specific 403 fallback route with configured-auth checks. Cost and token data distinguish input/output/cache reads/cache writes; zero configured local cost is not zero resource usage.

## Tools, policy and processes

The default registry includes read/grep/find/ls/bash/edit/write/webSearch/webFetch/todo/repo/sourceContext/memory/artifact/taskState/runtimeObservation/episode/job/check/verify; task/explore are appended unless disabled. Visual tools are capability gated. Optional append/diff/editPreview/editApply/submitPlan/compact surfaces remain registered/available according to runtime selection, not all default visible.

`safety-policy.ts` separates disabled, interactive, planning, autonomous and headless modes; applies path and shell rules and optional approval callbacks. Extensions are trusted differently by mode. It is an application policy, not an OS isolation guarantee. `sandbox.ts` and `tools/bash-sandbox.ts` provide optional process isolation backends. `file-mutation-queue.ts` serializes built-in mutations; `file-mutation-transaction.ts` uses temp-file write, file fsync, rename and best-effort directory fsync. Specialized mutation tools must be audited separately.

`bash-executor.ts`, `tools/bash.ts` and output-retention/persistence helpers separate bounded presentation from full output. `job-registry.ts` launches detached jobs, stores PID/start-token/log/exit records under `.ag1/jobs`, polls and kills, and reports finished jobs. Linux PID start tokens improve job identity; this is not universal cross-platform supervision. `check-detect.ts` and `check-parse.ts` already understand multiple compiler families including Cargo; `check` has a 90-second deadline and redirects longer work to jobs. Browser/vision tools use Playwright, URL policies, static-preview checks and separate visual verification; web fetch has credential and SSRF controls. These browser automation dependencies may be optional sidecars, not reasons to bundle Chromium into the desktop shell itself.

## Persistence and recovery

`session-manager.ts` uses version-3 JSONL with parent IDs, branch summaries, compactions, labels, model/thinking changes and arbitrary custom entries. Append paths use a file lock; async appends serialize within an owner. Structural rewrites use temp/rename under the same lock and merge external appends. Corrupt sessions can be quarantined; migrations and derived caches are tested. Physical journal order and active branch order are distinct. In-memory compiler projection need not replace original durable evidence. Fork currently copies branch entries to a new session ID without transferring artifact closure; B04 demonstrates retained references becoming unreadable from the child store.

`agent-session-retry-coordinator.ts`, `request-failure.ts`, `agent-session-recovery-arbiter.ts` and `agent-session-recovery-replay-scheduler.ts` classify failures/backoff and arbitrate retry versus compaction ownership. Stale replay guards prevent resumed timers from targeting changed sessions. Abort/dispose must settle pending retry, compaction, direct bash and event work. Persistence failure produces `persistence_error`; unresolved pending message appends block later request admission.

Auth/settings use their own locks/merge rules. Memory, jobs, checkpoints, runtime/VRAM profiles, artifact catalogs and session journals do **not** constitute one transaction. No blanket claim of crash-safe persistence is justified; tests cover selected corruption/fault cases, not all machine power loss. See the defect ledger.

## Diagnostics, adjacent systems and unfinished work

`session-metrics.ts`, `session-debug-logger.ts`, `run-diagnostics.ts`, `context-audit-log.ts`, `prefix-shape.ts`, `cv-session-stats.ts`, `subagent-debug-recorder.ts` and HTML export expose usage, timing, tools, recovery, prefix/cache behavior and evidence. Full provider-context audit is opt-in via `AG1_CONTEXT_AUDIT_DIR`, synchronous and redacted heuristically. It should remain opt-in and bounded. `context-replay-eval.ts` scores required/forbidden retrieval, budgets, freshness, rehydration, task/claim/evidence parity; tests and fixture paths are listed in TEST_STRATEGY.

`auton/index.ts` explicitly says the old autonomous runner/ledger/hook was removed; snapshot/format helpers return undefined/empty. Workspace preparation/diff/promotion remains active through interactive actions. Do not resurrect the removed autonomy system from old docs. `workflow-engine.ts` contains a DAG runner, but `/workflow` currently loads/validates and steers a text plan asking the agent to use task; it does not call `runWorkflow`. `mcp-client.ts` implements a stdio client and tool adapter but has no inbound production caller found; its header's Streamable HTTP promise is not established by implementation. These are partial/unintegrated, not default capabilities.

`packages/mom` is a separate Slack bot integration with channel context/store/events/tools; `packages/pods` a separate SSH/GPU pod/vLLM administration CLI; `packages/web-ui` a Lit-based UI library/storage/tool rendering, not the target React desktop. Keep their reusable public behavior accounted for without making Slack or cloud pod management desktop MVP requirements. Godot is a real native embedding and contributes mandatory native protocol/evidence parity fixtures.

The strongest clean seam is the SDK session/runtime facade plus an explicitly specified protocol. The existing RPC transport lacks durable event sequence/replay, comprehensive task/artifact/runtime APIs and bounded backpressure. Core tool definitions still import TUI `Text`/themes; mode-level addenda, verification, slash commands, approval dialogs and process cwd changes prevent calling the present implementation completely UI-independent.
